Вот финальная, полностью согласованная спецификация языка **Arc** (версия 0.8), включающая все принятые архитектурные и синтаксические решения.

# Спецификация языка Arc (v0.8)

**Философия:** «Честность системного кода без бойлерплейта и скрытой магии».
**Ниша:** «Rust минус borrow checker» — прямое ручное/RAII управление памятью, отсутствие GC и тяжелого рантайма, прозрачность размещения данных на уровне C.
**Целевые платформы:** Linux/macOS + freestanding (ARM Cortex-M, RISC-V), архитектуры x86-64 / ARM64.
**Пайплайн:** Лексер с ASI → Парсер → AST → Резолв → Тайпчек → IR → C99 эмиттер → Clang.

---

## 1. Лексическая структура и разделители (ASI)

### 1.1. Виртуальные точки с запятой (Automatic Semicolon Insertion)

Язык не требует обязательной `;` в конце каждой строки. Лексер виртуально вставляет токен `SEMICOLON` между токенами `A` и `B`, если между ними есть хотя бы один символ перевода строки (`\n`), и выполняются два условия:

1. **Токен `A` (слева) завершает выражение/инструкцию:**
   - Литералы (`42`, `"hello"`, `true`, `false`, `null`)
   - Идентификаторы (имена переменных, типов, функций)
   - Закрывающие скобки: `)`, `]`, `}`
   - Управляющие операторы: `return`, `break`, `continue`
   - Постфиксный оператор распаковки/паники: `!`
2. **Токен `B` (справа) не является токеном продолжения выражения:**
   - Токен `B` — это **не** точка `.`, не бинарный оператор (`+`, `*`, `==`, `&&` и т.д.), не `orelse`, не `catch`.

Явная точка с запятой `;` поддерживается и используется для записи нескольких инструкций на одной строке.

### 1.2. Ключевые слова

`const`, `let`, `fn`, `struct`, `impl`, `trait`, `dyn`, `if`, `else`, `while`, `for`, `in`, `return`, `break`, `continue`, `orelse`, `catch`, `try`, `defer`, `errdefer`, `export`, `import`, `from`, `extern`, `null`, `true`, `false`, `comptime`.

Зарезервированные сигилы:

- `#` и `#!` — зарезервированы под директивы и атрибуты компилятора (`#packed`, `#!no_prelude`).
- `@` — зарезервирован под встроенные функции компилятора (`@volatile_read`, `@size_of`).

## 2. Профили сборки и Freestanding

### 2.1. Оси конфигурации

- **Target:** `hosted` (ОС, libc) / `freestanding` (Bare-metal, микроконтроллеры).
- **Checks:** `safe` (проверки переполнений, границ слайсов, карантин памяти) / `unsafe`.
- **Size:** `speed` (-O3, инлайнинг) / `small` (-Os/-Oz).

### 2.2. Уровни стандартной библиотеки (`--profile=core|alloc|std`)

| Профиль   | Доступный функционал                                                                                     | Требования к окружению         |
| --------- | -------------------------------------------------------------------------------------------------------- | ------------------------------ |
| **core**  | `panic`, `assert`, `len`, `size_of`, `dbg`, `Arena`, `Allocator`, `fmt`, срезы `T[]`, `str`, `T?`, `T!E` | Пользовательский `__arc_panic` |
| **alloc** | Динамический `array<T>`, `string`, `box<T>`                                                              | Наличие аллокатора             |
| **std**   | `print`, I/O, файлы, сеть, потоки                                                                        | Полноценная ОС                 |

- В профиле `freestanding` запрещен `array<T>()` без явной передачи локального аллокатора/арены.
- `fmt` входит в `core` (форматирование в статический буфер без аллокаций).

## 3. Модули и Prelude

### 3.1. Структура модулей

- **1 файл = 1 модуль.**
- По умолчанию все сущности внутри файла приватны. Ключевое слово `export` открывает доступ снаружи.
- Точечный импорт: `import { read, write } from "sys/io"`
- Импорт пространства имен: `import io from "sys/io"`
- Глобальная распаковка `import *` запрещена.

### 3.2. Механизм Prelude (затенение без редакций)

Prelude подмешивается на стадии разрешения имен с **минимальным приоритетом**:
$$\text{Локальные переменные} \to \text{Явные импорты (import)} \to \text{Prelude}$$

Любое пользовательское объявление молча затеняет имя из prelude. Добавление новых имен в prelude в будущих версиях языка никогда не ломает существующий код.

## 4. Переменные, типы и память

### 4.1. Объявление переменных

Только `const` (неизменяемая) и `let` (изменяемая):

```arc
const max_retries: i32 = 5
let count = 0
count += 1
```

### 4.2. Базовые типы

- Целые: `i8`, `i16`, `i32`, `i64`, `u8`, `u16`, `u32`, `u64`, `usize`, `isize`
- Числа с плавающей точкой: `f32`, `f64`
- Логический: `bool`
- Пустой: `void`, невозвратный: `never`

### 4.3. Структуры и раскладка в памяти (Struct Layout)

- **Принцип WYSIWYG:** Раскладка полей в памяти **строго соответствует порядку объявления** (как в Си, Go, Hare).
- Компилятор **не переставляет** поля автоматически. Поведение 100% предсказуемо при отладке и C ABI совместимо.

```arc
struct Header {
    magic: u32
    version: u8
    flags: u8
}
```

### 4.4. Указатели и семантика перемещения

- **Non-null по умолчанию:** Тип `*T` гарантированно не равен `null`. Nullable-указатель объявляется как `*T?`.
- **Авто-разыменование (Smart Dot):** Доступ к полям и методам через указатель идет через точку: `ptr.field` вместо `(*ptr).field`.
- **Move vs Copy:**
  - Если тип реализует деструктор (`Drop`) — применяется семантика **Move**.
  - POD-типы (без `Drop`) — неявно копируются (**Copy**).

## 5. Трейты и `dyn Trait`

### 5.1. Правило владельца (Go-модель для методов)

- `impl Type { ... }` и `impl Trait for Type { ... }` разрешены **только внутри того модуля, где объявлен `Type`**.
- Резолв вызова `x.foo()` — это плоский поиск в модуле-владельце типа `x`.
- Соответствие трейтам **всегда явное** через `impl Trait for Type`.
- Отсутствует необходимость в _Orphan Rules_ — исключены неоднозначности при импортах.

### 5.2. `dyn Trait` (Sized Fat-Pointer)

- **Unsized типов (DST) в языке нет.**
- `dyn Trait` — это тип с фиксированным размером **16 байт**: `ptr (8B) + vtable (8B)`.
- Передается по значению, хранится в структурах и массивах без боксинга:

```arc
trait Drawer {
    fn draw(self: *Self, canvas: *Canvas): void
}

fn render(item: dyn Drawer) {
    // вызов: item.vtbl->draw(item.ptr, canvas)
}
```

- Владеющая динамическая форма использует умный указатель: `box<dyn Drawer>`.

## 6. Аллокаторы и коллекции

### 6.1. Хранение аллокатора внутри контейнера

Контейнеры (`array<T>`, `string`, `box<T>`) хранят аллокатор полем внутри структуры:

```c
typedef struct { void *data; const AllocatorVTable *vtbl; } Allocator; // 16 байт
```

- Размер `array<T>` = 32 байта (`ptr` + `len` + `cap` + `allocator`).
- Размер `box<T>` = 24 байта (`ptr` + `allocator`).

Это обеспечивает автоматический вызов деструкторов (`drop`) и возможность роста (`push`) без ручного протаскивания аллокатора через сигнатуры методов.

### 6.2. Коллекции и слайсы

| Тип        | Размер                | Владение             | Назначение                |
| ---------- | --------------------- | -------------------- | ------------------------- |
| `T[N]`     | `N * size_of(T)`      | Стек / Значение      | Фиксированный массив      |
| `T[]`      | 16 байт (`ptr + len`) | Не владеет           | Срез (слайс) памяти       |
| `array<T>` | 32 байта              | Владеет (куча/арена) | Динамический массив       |
| `str`      | 16 байт (`ptr + len`) | Не владеет           | UTF-8 строка-срез         |
| `string`   | 32 байта              | Владеет              | Динамическая UTF-8 строка |

### 6.3. Операции над строками

- Прямой доступ по индексу `s[i]` **запрещен** компилятором во избежание скрытой сложности $O(N)$.
- Побайтовый доступ (O(1)): `s.byte(i): u8`.
- Доступ к Unicode-символу (O(N)): явный метод `s.nth_char(i): u32?`.
- Итерация: `for ch in s.chars()`.

## 7. Опционалы (`T?`) и Null

### 7.1. Встроенный тип `T?`

- Не является дженериком, встроен в компилятор.
- **Niche Optimization обязательна:** Для указателей `*T?` значение `null` представляется как `0x0`. Размер `*T?` равен 8 байтам (оверхед = 0).
- `null` — контекстный литерал, не имеющий самостоятельного типа.

```arc
let user: *User? = null     // Корректно
let raw: *User = null       // Ошибка компиляции: *User не может быть null
```

### 7.2. FFI-границы

Все сишные функции, возвращающие указатели, в блоках `extern` обязаны возвращать `*T?`.

---

## 8. Обработка ошибок

### 8.1. Формы отказа

1. `T?` — неудача без диагностических данных (символ не найден, ключ отсутствует, память кончилась).
2. `T!E` — ошибка с типизированными данными (enum вариантов ошибки).

`T!` (со стиранием типов) запрещен во избежание разрыва статического анализа стека и скрытых аллокаций.

### 8.2. Конструкции обработки

- **Ранний выход / значение по умолчанию:**
  ```arc
  const user = find_user(id) orelse return null
  const port = get_env("PORT") orelse 8080
  ```
- **Паника / распаковка:**
  ```arc
  const first = list.nth(0)!  // Паника, если null/error
  ```
  _Примечание: `x!` запрещен в позиции lvalue (`x! = 5` — синтаксическая ошибка)._
- **Проброс ошибки:**
  ```arc
  const data = try parse_file(path) // Сахар над catch |err| return err
  ```
- **Сопоставление и захват:**

  ```arc
  parse_int(s) catch |err| {
      log_error(err)
      return 0
  }

  if opt |value| {
      print(value)
  }

  if opt |*value| {
      value.counter += 1 // Захват по указателю для мутации
  }
  ```

## 9. Выражения и управляющие конструкции

- `if` / `while` / `for` являются **statement-конструкциями** (инструкциями), а не выражениями.
- **Блок-выражение** допустим **только** справа от операторов `orelse` и `catch`:
  ```arc
  const config = load_config() orelse {
      log_warn("Default config used")
      DefaultConfig()
  }
  ```
- Управляющие операторы `return`, `break`, `continue`, `panic` имеют тип `never` и могут подставляться в правую часть `orelse` / `catch`.

## 10. Грамматика (EBNF)

```ebnf
(* Верхний уровень *)
Program         ::= Statement* EOF
Statement       ::= ( VarDecl | FnDecl | StructDecl | ImplBlock | TraitDecl
                    | ReturnStmt | BreakStmt | ContinueStmt
                    | IfStmt | WhileStmt | ForStmt | DeferStmt | ExprStmt ) Semicolon?
Semicolon       ::= ";" | NEWLINE

(* Объявления *)
VarDecl         ::= ("const" | "let") IDENT (":" Type)? "=" Expr
FnDecl          ::= "fn" IDENT "(" ParamList? ")" (":" Type)? Block
ParamList       ::= Param ("," Param)*
Param           ::= IDENT ":" Type

StructDecl      ::= "struct" IDENT "{" StructField* "}"
StructField     ::= IDENT ":" Type Semicolon?

TraitDecl       ::= "trait" IDENT "{" TraitMethod* "}"
TraitMethod     ::= "fn" IDENT "(" ParamList? ")" (":" Type)? Semicolon?

ImplBlock       ::= "impl" (IDENT "for")? IDENT "{" FnDecl* "}"

(* Управляющие конструкции *)
IfStmt          ::= "if" Expr ("|" ("*")? IDENT "|")? Block ("else" (IfStmt | Block))?
WhileStmt       ::= "while" Expr ("|" ("*")? IDENT "|")? Block
ForStmt         ::= "for" IDENT "in" Expr Block
ReturnStmt      ::= "return" Expr?
BreakStmt       ::= "break"
ContinueStmt    ::= "continue"
DeferStmt       ::= ("defer" | "errdefer") Statement
Block           ::= "{" Statement* "}"

(* Выражения *)
ExprStmt        ::= Expr
Expr            ::= Assignment
Assignment      ::= LogicalOr ( ("=" | "+=" | "-=" | "*=" | "/=") Assignment )?
LogicalOr       ::= LogicalAnd ( "||" LogicalAnd )*
LogicalAnd      ::= Equality ( "&&" Equality )*
Equality        ::= Relational ( ("==" | "!=") Relational )*
Relational      ::= Additive ( ("<" | "<=" | ">" | ">=") Additive )*
Additive        ::= Multiplicative ( ("+" | "-") Multiplicative )*
Multiplicative  ::= Unary ( ("*" | "/" | "%") Unary )*
Unary           ::= ("!" | "-" | "try") Unary | Postfix

Postfix         ::= Primary (
                      "(" ArgList? ")"             (* Вызов функции *)
                    | "." IDENT                    (* Доступ к полю *)
                    | "[" Expr "]"                 (* Индексация *)
                    | "!"                          (* Unwrap / Panic *)
                    | "orelse" (Block | Expr)      (* Обработка отсутствия *)
                    | "catch" ("|" IDENT "|")? (Block | Expr) (* Обработка ошибки *)
                  )*

Primary         ::= IDENT | NUMBER | STRING | "true" | "false" | "null" | "(" Expr ")"
ArgList         ::= Expr ("," Expr)*

(* Система типов *)
Type            ::= ("*" Type)                     (* Non-null указатель *)
                  | (Type "?")                     (* Опционал *)
                  | (Type "!" Type)                (* Ошибка Result *)
                  | (Type "[]")                    (* Срез *)
                  | (Type "[" NUMBER "]")          (* Статический массив *)
                  | "dyn" IDENT                    (* Трейт-объект *)
                  | IDENT ("<" TypeList ">")?      (* Именованный / Дженерик тип *)

TypeList        ::= Type ("," Type)*
```

## 11. План первой реализации: Срез Arc0

**Цель:** Скомпилировать алгоритм вычисления чисел Фибоначчи и вывести результат через C99.

### Входной файл (`fib.arc`):

```arc
fn fib(n: i32): i32 {
    if n <= 1 {
        return n
    }
    return fib(n - 1) + fib(n - 2)
}

fn main(): void {
    let result = fib(30)
    print(result)
}
```

### Реализуемый состав компилятора:

1. **Лексер:** распознавание ключевых слов `fn`, `let`, `const`, `if`, `else`, `return`, базовых токенов и реализация правила ASI для `\n`.
2. **Парсер:** построение AST для функций, вызовов, бинарных операторов и условий.
3. **Эмиттер C99:** генерация чистого Си-кода (`stdint.h`, `stdbool.h`, `int32_t`, `printf`).
4. **Сборщик:** вызов `clang -O3 output.c -o fib` и запуск.
